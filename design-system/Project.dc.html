ProjectScreen

The project profile page — route /projects/[id]. The detail view behind the Projects table and the project filter chips on the Activity page. It is deliberately a zoomed-in sibling of ActivityScreen: same summary strip, same merged-timeline + rail grid, same dense rows, badges, chips and data table — scoped to one project. No new design language, only project-scoped composition and five small new patterns.

Page anatomy

Top → bottom. One serif "spine" (the timeline) carries the narrative; everything else is compact reference. This is the answer to "four data types without four stacked tables": events are the spine, repos are a single short table, and knowledge + tasks are lightweight rail lists.

Section decisions

Identity block — the tree lives here

The breadcrumb (.sds-crumbs, Space Mono 11px) walks up: Activity / Projects / WeGovNYC / Databook — the parent is a link, the current project is aria-current="page". The first crumb is the route back to the Activity stream. Name (Fraunces, clamp 2→3rem), status .sds-badge and focus .sds-tag sit on one baseline-aligned wrap row so they never collide on narrow widths.

Child-project navigation is the same chip rail. On a leaf like Databook it renders siblings ("Also under WeGovNYC"); on a parent (the WeGovNYC page) relabel it "Child projects" and point it at the children — identical markup, one label swap.

pad-block clamp 2→3remrow gap 14pxsummary max 44remtree gap 9px, label 10px mono

Stats strip — identical register to Activity

Reuses .sds-summary verbatim so the two pages read as one system. Three derived numbers (cheap to compute): repo count, event count (with a 90-day delta), last-active date. The last cell is the right-aligned "↻ synced from GitHub" note, exactly as on Activity. Fraunces numerals, Space Mono labels.

cell pad 13×22pxnumber 23px seriflabel 9.5px mono / .09emlast cell margin-left:auto

Repositories — the one table on the page

Only 3 rows × 2 fields, so a full .sds-dtable is warranted and keeps repos scannable and sortable without competing with the timeline. Repo names are the maroon mono .repo-nm; a primary tag marks the lead repo; the trailing cell is the ↗ link-out. Placed above the fold of the two-column grid because "repo count" is a headline stat — the table is its expansion.

row pad 11×16pxdivider 1px≤720px hides "Last pushed" column (.sds-dtable--repos)

Activity timeline — the spine (2fr / 1fr)

Reuses .sds-timeline-grid and .sds-trow from Activity, filtered to this project. Each row: mono date · ringed .sds-tdot colored by kind (code / repo / release) · maroon-mono repo · Fraunces title · then a meta line carrying the authorship glyph, the @actor, and the diffstat or event kind. A curator note, when present, drops below as a Fraunces-italic aside with a saffron left rule (.sds-note). Pinned events get a gold ◆ (.sds-pin) — the project-scoped equivalent of Activity's pinned rail.

grid 2fr / 1fr, gap 20pxrow 56 / 16 / 1fr, pad 12×16pxtitle 14.5pxmeta 11px mono

Context rail — Knowledge, then Tasks

Two stacked .sds-log modules with mono .sds-dlist__head headers, built from .sds-prow rows — lists, not tables, so they stay quiet next to the spine. Knowledge rows carry the .MD/.HTML stamp, a pin ◆ when pinned, a mono dateline, and a one-line summary. Task rows carry a status .sds-badge. On the reached/Done task the badge is the solid maroon --reached variant.

module gap 1.5remrow .sds-prow, pad 13×16pxheader 10px mono

Authorship glyphs

Display-only marks on each event, sourced from a commit-trailer / frontmatter convention or a manual tag (a product decision, not a design one). Color follows the brand: maroon for human, saffron-ink for shared, muted for machine.

● Human — .sds-glyph--human ◐ Human + AI — .sds-glyph--hybrid ◑ AI — .sds-glyph--ai

Empty states

A freshly declared project may have no repos, no events, no knowledge, no tasks. Every list renders .sds-empty instead — a soft dashed panel with a mono headline and an optional plain-language hint — so the page degrades gracefully rather than showing an empty table frame. The stats strip still renders (0 / 0 / "—"), and the identity block always renders.

Responsive behavior

  • ≤720px — the .sds-timeline-grid collapses to a single column (rail modules fall below the timeline), reusing the existing dashboard breakpoint. Verified: grid resolves to one 359px track at 375px.
  • ≤720px — the Repositories table drops its "Last pushed" column (.sds-dtable--repos), keeping repo name + link-out.
  • Identity .sds-phead__row and the tree chips wrap; the name clamps 2rem → 3rem. No horizontal scroll at 375px.
  • Server-rendered, links only — no client JS. Filtering/sorting is delegated to the Activity page (/activity?project=…), which the "View in the activity stream ↗" link targets.

New CSS (additions only — nothing restated)

Appended to src/styles.css under a "Project profile page" banner. Everything else on the page is the existing v0.3 dashboard kit.

  • .sds-crumbs — breadcrumb (mono, links, muted separators).
  • .sds-phead / __row / __name / __summary / __tree / __tree-label — the identity block.
  • .sds-glyph + --human/--hybrid/--ai — authorship marks.
  • .sds-actor (mono @handle) and .sds-note (Fraunces-italic curator aside, saffron rule).
  • .sds-pin — the gold ◆ pin marker.
  • .sds-empty + .sds-empty__hint — the declared-project empty state.
  • Responsive: .sds-dtable--repos column drop + .sds-phead__row gap tighten.
